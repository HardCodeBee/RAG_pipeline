# r01 输入与输出约定（初稿）

- 保留冻结R02/v12的描述式分解，不把自然语言子问题自动改成#占位符链，也不改步骤顺序或双路检索。
- rewrite消费原当前问题和之前的Answer事实句；输出仍是一条检索问题。无历史时沿用原路线，不新增改写调用。
- ordinary接收原题、原始当前子问题、全部之前的Answer、当前双路合并reader以及本次实际用于检索的问题。最后一个字段是新增上下文，不能把这套候选称为纯文字替换实验。
- ordinary输出Support和Answer。原始全文完整保存，只有Answer进入后继history、改写和final普通QA区。Support不是额外证据，不累积到下一步。
- goal使用原题、ordinary Answer、goal双路合并reader和goal检索改写；不把原题复制成第二个Current字段。输出Facts、Link、Candidate，全文进入final综合区。
- final继续看到普通QA与原query的root Top10，另看到完整goal三字段。此稿不添加goal原始检索段落、重排、检索轮次或验证器。
- 输出标记是待实现的解析约定；旧短句formatter不能直接处理带字段的原始全文。新Answer原则上已是完整事实句，拟不再二次LLM扩写，需作为独立实现差异披露。
- 示例必须用虚构实体和自包含描述，与上游生成和下游消费格式一致。模型没有执行本初稿，任何人工参考输出都不是实验结果。

初稿待检查：字段完整性与异常分支；替代求解与缺证弃答的边界；final是否有足够材料纠正错误goal；是否因为要求完整句而丢失有用的部分答案；额外检索措辞字段的收益和锚定风险。


## r02修订

普通Support只留在本轮原始记录；Answer必须包含当前所问的必要事实与限定。goal三字段都进入final，Candidate不享有特殊可信度。final缺少goal原始reader并不自动否定goal带来的新事实。

字段仅在完整stop响应上解析；恰好出现一次、按顺序出现并且非空。缺字段、重字段、前导解释或输出协议不符记为格式失败，不用第二个LLM修复、不从Support猜Answer、不沿用旧缓存答案。解析成功只说明格式成立，不证明语义正确。完整原始输出和解析结果分别保存。

新普通Answer不调用旧短句formatter。保留旧P02完整对照；未来若解释收益来源，必须把是否formatter、额外检索措辞输入、输出上限等差异单列，不能把联合差异全部称为CoT收益。

词数为软目标，程序不能据此截短输出或材料。具体API输出上限尚未构成新评估协议；第一次实测需同步冻结对照额度并检查正常完整结束。
