# r01 首轮实质审查

本轮检查的是设计逻辑与人工示例；没有模型输出，不能称模型通过/失败。r01保留原文，不回写掩盖问题。

| 编号 | 发现 | 影响 | r02处理方向 |
|---|---|---|---|
| C01 | family_role段落只写child/parent，答案却确定father | 人工示例自身增加了性别/亲属角色，违反目标 | 把示例证据明确写为father，另加parent不足以推出father的检查项 |
| C02 | final示例拿到了goal的全部原材料 | 比真实P02的final更容易：真实final只拿root，goal补充检索新事实靠goal文本传递 | final示例显式分别构造root与goal reader，至少有一个答案事实仅经goal文本到final |
| C03 | 对不完整列表只示范无法比较 | 模型可能把任何非全列表都拒绝，包括已知下界足以决定比较的情况 | 配对示范：下界2对总数3不能定，下界4对总数3可以定 |
| C04 | Support/Answer是新增协议，尚无解析规范 | 无法判断缺字段、重复字段、空字段或续写的处理，可能静默丢信息 | 写清单次输出解析、无自动LLM修补、原始全文留存；不把参考句当生成结果 |
| C05 | ordinary同时看raw与retrieval question，但只口头宣称后者不权威 | 新检索措辞仍可能把人物或关系锚定错；已有D1局部改善不保证泛化 | 加错误检索措辞与正确原题/材料冲突的ordinary示例；保留该字段为显式候选因素 |
| C06 | goal的Facts标签容易被理解为已验证事实 | Facts仍是同一模型选择和表达的候选信息，final无法独立证实所有内容 | 在接口文档与final说明明确其来源；不可声明“验证通过”或用生成的依据当第二个独立来源 |
| C07 | 原句formatter与新字段接口关系未彻底解决 | 把Support+Answer全文塞入旧formatter会改写意义；取消formatter也有比较混杂 | 候选仅解析Answer并不调用旧formatter；旧控制保留原流程；统一格式支路另作控制而非暗改 |
| C08 | goal输出不说明简短直接题可以不展开推导 | 无条件解释容易新增无关事实或强造链条 | Link允许一句直接依据；不要求逐个子问题复述，也不把规划链视为唯一解法 |
| C09 | final的最短完整答案与多候选保留存在张力 | 可以不必要地列出所有相关事实，或为单数提问杜撰唯一对象 | 明确只保留回答所问的内容；多个满足条件者无依据唯一化时，不增加排名或过滤规则 |
| C10 | 只有缺证示例，没有布尔短路示例 | 一个必要条件已为假时，其他未知不应强制弃答 | 添加AND中一个明确否定足以No的示例，OR/unknown作为静态挑战 |

首轮保留的设计选择：R02不变；rewrite仍只产出检索问题；普通Support仅本阶段记录；goal完整综合交给final；final保留root材料独立纠错能力；不扩大检索包、不让同题所有原始材料无条件累积。

这些修改处理可明确定位的自相矛盾和示例失真，不构成已证实的性能改进。r02仍需单独检查过严弃答、冗余、字段破坏及真实旧案例的可解释性。
