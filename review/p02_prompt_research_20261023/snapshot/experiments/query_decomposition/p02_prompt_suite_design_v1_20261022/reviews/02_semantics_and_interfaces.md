# 第二轮：逐阶段示例与信息交接复核

本轮审核r02，修改保存在r03。结论是设计修改，不是模型验证。

| 发现 | 为什么需要修改 | r03处理 |
|---|---|---|
| family goal的Link提到Marek是Liora的父亲，但这一关系仅在ordinary示例reader中出现，未进入该goal实例输入 | 同一故事不能替代真实的数据交接；会教出无依据补充 | 删去无输入支持的旁支，只写Tomas→Orin→出生地的必要连接；同步final输入 |
| “缺证则说明缺口”可能被读成没有新passage重复旧答案就必须弃答 | 旧Answer仍是方法的重要信息来源；要求重复证明会切断流程 | 明确已有答案可以使用，不伪造passage佐证；保留事实正确性与来源可信度的区别 |
| “有冲突就用passage”缺少实体、年份与范围复核 | 旧时信息和当前信息未必冲突，同scope多源冲突不能靠先后顺序解决 | 写清匹配实体/关系/时间/范围后处理，仅无法解决的必要冲突阻止结论 |
| ordinary有缺证弃答示范，却没有真实但不完整的列举答案 | 与既有标注边界不一致，可能诱导过度弃答 | 增加仅知一部小说仍保留真实条目并说明非全集的示例 |
| final已有属性纠错，缺少正确中间实体到原题所问对象的回映射 | “导演年龄比较正确、却输出导演而非电影”无法靠实体绑定全部覆盖 | 增加电影/导演的final-only错误Candidate纠正示例 |
| 字段约定散落于文档，prompt没有明确固定顺序/无前导说明 | 解析器不能用宽松猜测来补救生成偏差 | 每个结构化prompt明确标签、顺序及段落；异常保留原文并标识 |
| goal下界两个例子相隔较远 | 都是计数却需要相反结论，适合并列比较 | 排列为不充分2对3、充分至少4对3；不是增加通用“认真推理”口号 |

没有因上述修订声称新方案必然有效。额外检索措辞仍可能造成锚定，普通Support仍可能解释错误，goal仍可能包装错误结论；这些必须在真实模型及后继检索中检验。
