# 第四轮：尝试反驳候选，而非只检查正向示例

## 最值得质疑的三个选择

**新接口可能抵消新示例的好处。** Support/Answer让普通模块多生成文本、需要字段解析，并取消旧formatter。即使local Answer更正确，Support错误、字段失败或长度增长也可能增加。保留整套设计作为可检验候选，后续不将这些差异隐藏成“只适配格式”。

**显式展示改写也可能放大错改写。** 原始描述与检索问题共存并非天然比只给原始描述更可靠。r03用导演/制片人示例说明检索措辞可能错，并有县治挑战；只有真实生成才能确定模型是否遵守。这一因素如果表现不佳，可独立去掉检索措辞字段，不能无证据宣布必须保留。

**goal的正确说明可能只是事后包装。** 正确的Facts并不保证Link有效；Link正确也可能映射到错误答案类型。自然语言输出无法保证忠实于内部推理。final-only反例旨在训练检查任务，并不提供独立事实验证器。新稿仍可能像之前GF/GO一样退步。

## 尚未通过模型验证的平衡

| 张力 | 设计选择 | 检查失败时怎样解释 |
|---|---|---|
| 不猜测 vs 保留事实正确的外部知识 | 不额外添加“答案不逐字在passage就错”的评分要求；可用已有候选答案，不能伪造来源 | 真实可答题过度弃答是损害；不能用“更保守”遮盖F1回归 |
| 先前答案可用 vs 错误传播 | 检查同实体同scope冲突，保留纠正信息；不一律信或一律丢 | 无材料纠正的错误可能继续传播；属于架构现有限制 |
| 完整信息 vs 最短答案 | 普通Answer留必要条件；goal留必要关系；final只去掉不必要背景 | 删除必要消歧词是损害；输出所有相关实体也可能答非所问 |
| 充分性 vs 完整性 | 知道部分事实也可回答某些比较/布尔问题，不能把未知当否定 | 同样缺一项的题可能应答或应弃答，要按关系判断 |
| few-shot覆盖 vs 冗长 | 24例分属不同调用，单次不会吃到全部；只保留各阶段任务所需示例 | 成本与干扰增加需实测；没有假定示例越多越好 |

## 接口检查的能力边界

194项检查只是具体断言数量，不是194种独立能力。40个合成挑战做的是可渲染、原题保留、审核字段不进入实际任务等检查；其预期语义尚未由模型执行。没有“40/40语义通过”的结论。

字段解析核对已知标签、顺序、非空与前导说明；它不判事实真假，也不能识别任意一段文本是不是额外小标题或不必要解释。字段内部追加的自然语言可能仍被保留，这是复核对象，不能靠隐式清洗修正。final整体保留，甚至名称本身以Answer:开头也不盲目删除，否则可能误删真实作品名。

本次无网络推理、无新检索，只有先前研究阅读、人工设计、离线渲染及结构检查。旧生产文件和主评暂停标记仍通过起始哈希核对。未来B00会使用共同额度和完整响应接受条件，属于同协议控制；历史H保留原native行为，包括旧final允许截断的实现差异。二者不能混称同一个冻结对照。
