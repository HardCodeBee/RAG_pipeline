## 为什么研究这些问题

冻结分解器 R02/v12 已使用自包含描述式子问题，而旧子回答提示词保留 `#N` 指代示例。直觉上，改成与分解形式一致的示例应更合适，但此前完整流程的小样本比较没有支持这种直觉。本侧对话进一步研究：

- `#N` 的作用是否来自演示中间结果与后继问题的绑定，而不只是表面格式？
- 让 goal 显式说明关键事实、必要组合和候选结论，是否有助于 final 使用已有信息？
- few-shot、组合操作示例、目标解释和信息保留规则，分别带来什么收益与损害？
- 能否重新设计 rewrite / ordinary / goal / final 的接口，改善下游质量？

既有信息流诊断提示，应区分候选未覆盖、reader 选择丢失、回答未保留必要事实、错误组合和 final 选错属性。事实正确性不等同于求解信息充分性。研究论文仅用于提出假设，论文结果不作为本地效果证据；对应研究引用保留在各实验 README 和设计材料中。

## 到目前为止，证据支持什么

1. **格式一致并不是已证实的主要瓶颈。** 显式结果使用说明没有改善已判定普通节点；更长的组合说明也没有稳定提升最终答案。尚未用充分控制的实验单独证明 `#` 符号、实体指认或依赖绑定中的哪一项起作用。
2. **生成了组合说明，不代表组合正确。** 实际输出出现新增时间或唯一性条件、对象与属性混淆、将线索当作所问对象，以及因不必要的证据要求而弃答。部分正确短答案还伴随错误解释。
3. **普通QA、goal与final应分别定位。** 子问题完整事实句的真假、对后续是否有用、goal是否正确组合、final是否选中所问粒度，是不同问题。r03普通回答增加 Support 文本后成本升高，抽查主答案不变，不能把这些输出当作完整流程收益。
4. **更多约束和示例也可能引入负担。** r04已去掉新ordinary和新final，只改goal输出与目标规则，仍明显退步。这支持继续定位具体内容变化，而不支持把负结果泛化成“CoT无效”。

新60题的轻微改善和固定90题的退步都保留；未按最好的一次结果选择性报告。所有样本已用于开发或继承自既有评估，不是独立未见测试集。重复使用相同题目、控制回执与材料，会限制泛化判断；不同轮次的条件数不能相加解释为独立样本数。

## 数据与实现说明

- `snapshot/` 保持原仓库相对路径，保存原文件字节。内部旧链接若依赖未收录的大型训练材料、检索索引或账务数据库，不能视为本包具备该运行环境。
- `receipts/<实验>/` 是各实验 checkpoint 的全部数据表只读导出。JSON列解码为对象，逐表采用 `.jsonl.gz`，保留完整请求、返回、usage、状态、历史失败和映射；不附运行中的SQLite、锁文件或全局账务数据库。
- `prompt_examples/` 各组提供一个完整实际请求与回答入口；全部请求在 receipts 中。参考答案与诊断标签另存，未加入模型输入。
- `scoring/` 包含本包所需的冻结参考答案及2Wiki原始别名子集；原生评分代码在 snapshot 中。
- [INVENTORY.json](INVENTORY.json) 将本对话实验、实现依赖和其他对话的参考研究分开标记。局部CoT、共享上下文、此前三prompt联改等只作为背景，不冒充本对话新完成的实验。
- `MANIFEST.json` 给出交付文件校验值。旧协议中的 `publication:false` 表示当时实验没有发布；本次发布由用户随后“将我在这个对话进行的一系列实验打包 送往远端”，以及“不新建分支”明确授权，历史协议不回写。

本包不含API密钥、远端密码、全局账务库、模型权重、完整语料索引或无关工作区改动。研究脚本原样保留以供审查，其付费执行入口依赖原运行环境和授权；本包提供的是**可独立离线重算的审核材料**。

## 离线复核

在本目录运行：

```bash
python -B verify_offline.py
```

仅依赖 Python 标准库；不会调用API、联网、改写源实验或启动评估。校验包括文件完整性、173项冻结引用、所有导出表行数、请求映射、usage总量、逐题原生F1/EM、已报告汇总值及后两轮配对变化。人工标签与bootstrap区间保留原脚本和结果，独立校验脚本不声称重新完成语义标注或重新抽样。

## 下一步仍待研究的问题

当前没有待自动执行的实验。后续应优先检查必要信息在ordinary、goal和final之间具体在哪一步丢失，围绕已经识别的失效做单因素内容对照；若重新提出候选，应保留冻结对照，并在未用于选提示词的独立样本验证。固定reader上的变化必须经过动态完整RAG验证，才可能改变主评估方法选择。
