# C8: make the existing rewrite the actual ordinary-QA task

This offline preparation freezes all eight I8 nodes, including six local QA failures and two reasonable-abstention boundaries. It tests whether changing the actual task has a different effect from the unsuccessful generic verification sentence and candidate-description block. It is an explicit new input variant; the original P02 implementation is not claimed to have used this input.

C0 exactly reuses the already paid fresh I0 payload and response. C1 replaces only the text value beneath the **Actual task** `Current subquestion #N` header with that same source node's saved `rewritten_query`. No replacement occurs in examples. Original question, history, reader, raw R02/v12 decomposition, instructions, examples, all other message bytes, model/settings and 128-token cap remain fixed. No goal, formatter, retrieval or final stage is run. No gold entity is inserted and no rewrite is manually corrected.

The evaluation target remains the **original raw Current subquestion** in both arms. Each future blinded packet must display that unchanged target separately from the actual question supplied to the model. A factually true answer to a deviating rewrite can still fail the original target; rewrite deviation and whole-statement errors must be recorded separately. True but incomplete responsive lists remain allowed; wrong extra members, off-target background and incorrect complete relations remain errors. Reasonable abstention and necessary-information retention are distinct fields. The Richard generation error already present in the decomposition and Hotpot122's old downstream recovery remain explicit boundaries.

There are 16 logical conditions but only **five new distinct payloads**. All eight C0 conditions reuse exact I0 receipts. The three C1 questions unchanged by their existing rewrite (Speedpass, Butautas, Cretan pack) must reuse those same I0 receipts too, with no request or new charge. The five changed questions (Richard, Liu, Wills, Tsutsunava, Jewel Staite) are queued in the original I8 case order. Controls are a historical exact reuse, not a new synchronous draw. Duplicate logical uses are not independent samples and do not dilute unique-payload costs.

This is a selected, repeatedly exposed eight-node local development screen, not overall accuracy, a fresh holdout, full-RAG F1 or evidence of exceeding original P02. Its nonconcurrent I0 reuse cannot establish a causal C benefit. Any apparent repair requires a new fresh synchronous all-eight-node validation before claiming benefit. First lock method-masked semantic reviews of the new answers; only then join methods. Report paired real repairs, harms and unaltered failures, not just string changes. If this stronger actual-task replacement does not repair the targeted failures, stop this entity-prompt branch without adding more same-case tuning.
