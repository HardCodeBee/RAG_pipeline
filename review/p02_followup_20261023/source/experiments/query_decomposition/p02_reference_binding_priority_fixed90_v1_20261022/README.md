# Full-RAG prompt-factor comparison: offline prepared

Prepared counterpart to `p02_reference_binding_priority_probe_v1_20261022`.
This directory contains the pure injected-service adapter and an isolated
controller, exact fixed90 source/resource copies, ORDER360, a protocol draft
and offline checks. The 360 conditions are C0/S1/B1/P1 on all90 cases; the same
engineering6 produce the first24 conditions. Preparation has created no API
request, SSH connection, GPU job, protocol freeze or execution authorization.
It has produced no complete-RAG results.

The intended comparison is C0/S1/B1/P1 on the same exposed fixed90 actual
R02/v12 cases. Each factor applies to every ordinary node; no-op bindings stay
in the planned denominator. B uses that arm's own newly accepted prior answers
and live native retrieval rewrite. It does not insert the historical stage
probe's answers, maps, rewritten queries or reader packets. New answers affect
the native subsequent rewrite and actual retrieval. Goal, the optional short
answer formatter, the final native root packet and final64 stay unchanged.

The existing core Pipeline is invoked unchanged. Raw and actual QA prompts,
candidate span supports and raw evaluation targets are retained in node metadata.
C0 must pass exact request and native trajectory equivalence against the core;
S1/B1/P1 must preserve all non-QA requests except changes naturally caused by
their newly produced answers. No current method, formal500 campaign or timing
campaign is promoted or resumed by this draft.

Stage-probe semantic correctness is separate from final native F1/EM. The new
controller waits for both exact predecessors (context270, including matching
worker closure; stage152) to have attempted all conditions with zero in-flight
requests. Held conditions count as attempted and are never blindly reissued.
This is a resource/execution guard, with no quality threshold.

The private SSH bridge inherits the pinned retrieval-only implementation and
uses a new factor90 namespace. EXECUTION_SETTINGS.json explicitly selects6hours
after the root's read-only db4ai partition preflight; jobs close on completion.
A15minute conservative dispatch margin keeps later conditions unstarted when
the allocation is nearly exhausted. The verified address supplies only a TCP
socket; the original hostname and strict host-key policy are retained.

NativeAsk, shared provider serialization, five durable technical attempts,
return/ledger guards and all unknown liabilities are preserved. Status and the
engineering gate do not compute native scores; score.py is a separate explicit
offline action. Root independent review, protocol freeze and exact-hash
authorization/decision are required before execution. See PROTOCOL.md and
HANDOFF.md for the frozen scope, checks and launch sequence.
