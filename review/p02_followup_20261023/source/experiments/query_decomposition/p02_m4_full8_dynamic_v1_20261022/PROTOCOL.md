# M4 complete dynamic RAG on the fixed stage8 queries

Offline preparation only. No RUN_AUTHORIZATION, API, SSH deployment or GPU job
is implied by this package. Root may authorize its exact frozen hash only after
the preceding stage16 blinded review and integrity audit establish substantive
recovery of requested information without a clear regression. Date precision
alone is not presumed to improve an official F1/EM endpoint. Main formal
evaluation remains paused; none of its STOP files or approval=false is changed.

Use exactly all eight full questions from the frozen M4 stage8 input, in its
existing order, without new selection or filtering on stage outputs. There are
eight distinct previously exposed 2Wiki queries and17 ordinary nodes per arm.
The prior stage selection deliberately contained a known loss case plus prior
successful and nonfullscore strata; this is selected development evidence, not
an unseen or representative evaluation. Same-source historical complete-RAG
references exist for all8, including one r100 source. Keep those nonconcurrent
references separate from both freshly executed arms.

Inference receives only id/qid/dataset/question/supporting_questions. Each
five-field record equals its hash-verified public formal runtime. Each actual
support array is checked against formal remote_raw R02/v12 output; no manual60
or query-only corrected decomposition is used. Source/public manifests and
original complete wire receipts are verified without reading the new stage
checkpoint, stage answers, method key or semantic endpoints. Native reference
answers/predictions remain separate local-only reporting inputs and never
enter Pipeline, retrieval worker requests or provider messages.

M0 uses the original interleave-original-first Top10 merge. M4 changes only
that merge call for **every ordinary and goal** node to the previously frozen
same-source ordered-word/punctuation fingerprint duplicate-fill rule. Native
Pipeline.execute is copied locally, with exactly one body line replaced; core
and global module state are not patched. M0 must reproduce the original native
trajectory, prompts, retrieval sequence, formatter and final wire on all8
recorded sources and deterministic injected tests. The M4 selector code is
imported from the frozen stage package, not retuned for this comparison.

All prompt instructions, demonstrations, Original question, raw Current,
history row.request, goal rule, rewrite acceptance and format rules remain
native. Do not combine live-current entity replacement, O1 original-question
deletion, ROLE instructions or synthesis output. M4 retains the first
interleaved candidate with exact doc.source article-title identity plus an
identical ordered case-sensitive word/punctuation token sequence, then fills
from the same union to10 and preserves union-relative order. Never collapse
different article titles, relation words, dates/units/case/word boundaries, or
complementary content from one title. Same as the exposed stage rule, if fewer
than10 distinct signatures exist, refill from the original pool to maintain10.

Both arms run freshly in one new checkpoint with no historical LLM or
retrieval seed. They may share an exact new payload or query/resource cache in
that checkpoint; record all logical uses while attributing each actual charge
to its first submitting condition only. Arm order rotates by fixed seed/case
index, four starts each, without score-based ordering. Every query/condition,
failure and regression stays in the report.

Each arm generates its own ordinary answers and consequent history. Subsequent
rewrites are recomputed from that history; changed accepted query strings
trigger real retrieval over the same frozen corpus/index. There are no frozen
reader replays in the actual experiment. QA and goal use128 output tokens;
strip+whitespace wordcount below4 invokes the exact native formatter128 with
raw Current, candidate and that arm's reader. Goal may receive a changed M4
reader, but the final root packet remains the original retrieval for the
original question, exactly as native. Final packaging/readout remains native
at64, accepting a complete matching-model/usage nonempty no-refusal length
receipt as success_truncated and scoring that actual text.

Remote retrieval uses the same verified portable2Wiki resources: BGE query
encoding on a newly authorized remote A6000 allocation, exact CPU FAISS,
query batch1, original per-qid allowed-document filtering and Top10. No local
GPU substitute or resource change occurs silently. Old source preflight is
provenance, not a claim of current readiness; the separately approved bridge
must recheck dependency, corpus/index/manifest, query-model bytes, runtime and
partition before allocation. Only qid/query/resource identity crosses SSH;
API keys, LLM messages, histories and local references stay local. New isolated
directory is `m4full8_<protocolhash16>`, with a separate deployment lock and
durable submission attempt. An unknown allocation receipt is not resubmitted
blindly. After worker completion, a missing new retrieval is held for root
technical reconciliation; no silent GPU reallocation. Worker idle/STOP belongs
only to this new job; old experiments and main STOP files remain untouched.

Reuse byte-identical native adapter, resource contract, retrieval bridge,
worker and model manifest from the audited balanced20 package. SDK/HTTP
retries0; real technical attempts total at most5 including initial and restarts.
The shared gate serializes real provider submissions with a3-second minimum
start interval. Preserve returned response/content/refusal/finish/model/usage
or ledger evidence and all unknown liabilities; do not blindly reissue them.
Ordinary/goal/rewrite/formatter success requires stop/nonempty/no-refusal,
exact requested+returned model, all3 nonnegative int token fields excluding
bool and exact sum. Full-integrity length/empty/refusal/filter is an algorithm
terminal0 without reroll. Missing usage/model mismatch/provider rejection or
technical exhaustion is held and produces fixed-N bounds, not a zero score.
The final native length exception above is stage-specific.

Report official native answerF1 and EM for old same8, freshM0 and freshM4 in
separate columns, with fixed8 denominator per fresh arm; complete-pair gains,
ties and harms; native F1==1 or EM==1 count separate from semantic correctness.
Initialize each dataset official scorer once (only2Wiki here). Incomplete
technical conditions give no full-N point estimate, with explicit lower/upper
bounds and missingness. Preserve initial/format outputs and full trajectory in
the checkpoint. Lock method-masked final text-difference review before
interpreting score differences; do not equate more precise dates, partial F1,
or old-to-fresh drift with a factual repair or stable benefit.

Logical complete-flow tokens/cost include shared new receipts; actual paid
attempts (including failed technical attempts) and unresolved reserves are
reported separately. No fixed cost ceiling. A paid query above3x its complete
same-query historical reference is flagged. The existing recent20-complete-
paid-query trend cannot be reached by this16-condition experiment alone; do
not substitute stage counts, pure caches, partial flows or unknown costs. No
timing benchmark or LLM-call-count metric is introduced here.

Offline prepare/dry/report never create a real Cache, provider client or remote
connection. Reports use SQLite mode=ro. Once all16 outcomes are terminal,
reentering run returns through read-only reporting before Cache/bridge/GPU
setup. Only a separately recorded root authorization binding protocol hash and
decision can begin inference. No automatic promotion, further sampling,
prompt combination or main-evaluation restart follows from this preparation.
